# EngineLink 0.13.4 — Wi-Fi channel diagnostics and beacon-loss recovery

- Record nearby access-point counts for channels 1–13, including stronger neighboring networks, survey age/duration/failures and machine-readable report fields.
- If an established router connection drops with reason 200 (beacons lost), try restoring 15 dBm TX power **after** the link reconnects. Limit this recovery to once every five minutes, and count actions in the report. This does not reconfigure or change the router channel.
- Retain compatibility with automatic router channel selection, 20/40 MHz router settings, and mixed WPA2/WPA3. Standalone Wi-Fi, router fallback, engine data and fuel calculations are unchanged.

**Important limitations:** An ESP32 station cannot choose the channel of an external router. Neighbor network counts are not airtime utilization or a measure of non-Wi-Fi interference. Increasing transmit power is an experiment, not a demonstrated cure for lost downlink beacons.

**Validation:** Automated compile and source checks must pass before merge. Real-router stability and throughput tests, including idle operation and long sessions, are still required. Update via the in-app Wi-Fi updater to preserve data; the full USB image is not a preservation update.
