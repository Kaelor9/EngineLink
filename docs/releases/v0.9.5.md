# EngineLink v0.9.5 — Reliable mDNS recovery

**Status:** ESP32-S3 alpha firmware. Build validation is not a substitute for a Wi-Fi test on the physical EngineLink PCB.

## What changed
- Keep **http://enginelink.local** available as the default local name on the EngineLink access point and on a compatible boat router.
- Detect SoftAP restarts and router DHCP acquisition, then refresh the mDNS responder after the interface has stabilized.
- Retry failed mDNS initialization every 15 seconds without resetting the access point or rebooting the controller.
- Verify that HTTP service registration succeeds rather than treating a successful mDNS initialization alone as proof of service readiness.
- Show mDNS responder status, retry count and current `.local` name in existing Diagnostics UI. No visual redesign.
- Preserve all other v0.9.4 engine, fuel and web UI functions.

## Fresh USB web installation
Use https://kaelor9.github.io/EngineLink/ **only once the manifest shows v0.9.5**. Chrome or Edge on desktop and a USB-C data cable are required. The full merged 8 MB USB image **replaces settings and internal history**. It does not erase a separate microSD card.

Disconnect J1708 and NMEA 2000 for initial flashing and hardware validation.

## Functional checks
1. On the EngineLink Wi-Fi, confirm http://192.168.4.1 and http://enginelink.local both load.
2. Connect to the boat router and check http://enginelink.local from a client on that router's LAN; if not available, use the router-assigned IP shown in Settings.
3. Repeatedly scan for networks, navigate pages and test download speed while watching phone drops, loop time and mDNS Diagnostics.
4. Disconnect/reconnect the router and check whether the responder restarts and `.local` works again.

**Limitations:** mDNS uses multicast UDP/5353 and requires client Bonjour support. Routers that filter client-to-client multicast, use client isolation, or separate VLANs may prevent `.local` even when the responder is running. The direct IP remains a reliable fallback.
