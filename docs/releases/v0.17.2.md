# EngineLink 0.17.2 — the Wi-Fi's buffers stay in internal memory

**Test version for the web installer. Built (pinned core 3.3.12 compile,
source checks); NOT verified on the board. Router mode on the owner's home
router is not fixed until a report shows it.** Hardware: revision 1 board,
ESP32-S3-WROOM-1-N8R8. USB installation erases settings and internal
history; the Wi-Fi update file keeps them.

## Why

0.17.1 (router joined straight after a start) stayed on the home router for
over 650 s and showed the app, but answers from the router took 441–770 ms
on average from the first seconds; the owner's plain sketch on the same
board and router had 10–50 ms. The one software difference left is PSRAM:
EngineLink runs with PSRAM on, and the ESP32 core then puts the Wi-Fi
driver's and lwIP's packet buffers in PSRAM whenever it has room. The
sketch's fast run had PSRAM off. Espressif's advice with PSRAM is to keep
Wi-Fi buffers in internal memory. Whether this is the cause on this board is
not proven; the owner chose to change it without a separate test.

## Changed

- **EngineLink takes all of the PSRAM for itself at start** (`psram.h`): 2 MB
  as its own pool for the engine frame queue, the sample rings and the web
  buffers, the rest held as spare. With no PSRAM free, the Wi-Fi's buffers
  land in internal memory. Documented ESP-IDF heap functions only.
- While EngineLink talks to GitHub (updates, reports) the spare part is lent
  back, because HTTPS needs about 40 KB at once.
- Safety valve: if internal memory runs low (largest free piece under
  12 KB) the spare part is given back for a minute; the report counts it.
- The report's memory line shows the pool, the PSRAM left for the system
  (should be near 0) and that count.

Unchanged: router mode joins from a clean start (0.17.1), Standalone,
recovery, the web server, the app, settings, engine data, trips, SD.

## Risk

More of the firmware now lives in internal memory (about 85–100 KB were free
before). This cannot be measured without the board: the report's "Memory"
and "Internal memory" lines after 10 minutes of use are the check. A
restart with reason 4 (crash) or "failed allocations" above 0 means it is
too tight.
