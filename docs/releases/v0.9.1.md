# EngineLink 0.9.1 — stabilize offline SoftAP

This release targets the owner's reported loss of EngineLink's **own Wi-Fi** at less than two metres even when no boat router is configured.

## Changes
- Standalone AP startup no longer enables STA mode and scans neighbouring channels to choose a channel. It uses the saved fixed 2.4 GHz AP channel (fallback 6) and does not scan or hop channels while running AP-only.
- AP recovery runs at a 15-second cadence, waits for a sustained stop event and avoids calling the low-level `esp_wifi_start()` from the watchdog. It lets `WiFi.softAP()` restore a genuinely failed AP.
- AP setup does not depend on an asynchronous AP_START event arriving before it can skip reapplying an otherwise unchanged configuration.
- **No visual/app changes, added authentication, additional hardware controls, J1708 commands, or storage migrations.**

## Verification limits and boat tests
- GitHub CI firmware build and host tests required before merging.
- **Not verified** on the actual ESP32-S3 board, radio, power supply or phone.
- Test AP only for at least 30 min, then AP+STA separately. Check whether the phone actually disconnects from Wi-Fi or just reports app "Reconnecting"; also inspect AP stop/start/leave counters and reset reasons.
- If AP-only disassociations continue on a stable build, check RF antenna placement and 3.3 V rail while transmitting; these cannot be corrected by changing the channel selection software.
