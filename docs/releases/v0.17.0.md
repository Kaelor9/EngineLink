# EngineLink 0.17.0 — Wi-Fi: two modes, documented station profile

**Status: 0.17.0-rc2 *built* (pinned core 3.3.12 compile, host tests and
source checks pass), not yet run on the board. rc1 was bench-tested on
2026-11-09 (15:37 build): standalone fine, the home router answered neither
auth nor association requests (reasons 2/4/15), so rc2 sets the station back
to the driver's defaults, exactly as the Prism controller. Not a release** until the one
bench session and the boat trip in
[WIFI_PLAN_2026-11-09.md](../WIFI_PLAN_2026-11-09.md) section 5 are reported
passed. No merge to `main` before that.

Why: router mode worked for hours on the boat router but never served the
page on the home 4G router, and every analysis step so far produced another
bench build. The 2026-11-09 review ([plan](../WIFI_PLAN_2026-11-09.md)
section 1) found the failure below the firmware's logic and a short list of
real firmware defects. This build fixes those, removes what the review
dropped, and leaves one session to tell router, place and board apart.

## Wi-Fi

- **Two modes, never both.** Standalone (own Wi-Fi at 192.168.4.1) and Router
  (station only). The 2 minute fallback to the own Wi-Fi and the 10 minute
  retry while no phone is joined stay as a **recovery mechanism**; the report
  now says "Router (router not reached; EngineLink Wi-Fi on meanwhile …)" and
  the app "Router not reached", instead of a third "Recovery" mode.
- **Station on the ESP32 driver's defaults, as the Prism controller (rc2).**
  `WiFi.mode(WIFI_STA)`, the core's own reconnect, `WiFi.begin()`; no
  power-save, country, bandwidth, scan or TX-power call on the station, and
  nothing polls the driver while it connects (the router's signal is read
  only when a report or the app asks). rc1's station profile (power save off,
  country DK, 20 MHz, all-channel scan) is gone; the comparison with Prism's
  code is in the plan, section 2.2.
- **Removed:** the unwired Wi-Fi 2.0 state machine (`wifistate.h`, Stage 4),
  the 0.15.0 leftovers (`netpolicy.h`, `routerguard.h`, the radio test and
  channel survey in `linktune.cpp`, the "rescue looks", the saved failure
  record and the always-0 report fields), and the NVS keys `rch`, `rrsn`,
  `rstage`, `rduration`.
- **Report:** the driver's country code is printed correctly (it was read past
  a 3-byte buffer: `DK ?\x01…`); the radio test, "rescue looks" and failure
  stage lines are gone; `mode` is `standalone`/`router` with `recovery`
  true/false.

## Web

- The 110 KB app page streams from the transfer task like the exports, so a
  phone on a slow link can no longer hold the server task while `/` is sent
  (2026-11-06: `/api/live` answered while `/` took 20 s). One request may wait
  behind a running transfer instead of getting 503; a third still gets 503.

Not changed: J1708 and KAD reading, NMEA 2000, trips, fuel, totals, storage
formats, settings, the update and rollback path, the app's screens apart from
the Wi-Fi texts. Settings and data survive the update.

## Verification (owner; plan section 5)

One bench session on the home 4G router with the PC's `ping -t` and
`netsh wlan show networks mode=bssid` logs running and the Prism controller as
control at the same spot: ≥ 99/100 pings, 20/20 `/api/live` within 2 s,
10/10 `/` within 5 s, 30 min without reason 200 or a fallback, report shows
power save off, country DK, 20 MHz; standalone unchanged. A failure is read
with the table in plan 5.4 — no new build for a diagnosis. Then one trip with
the boat router, including a router power-cycle.
