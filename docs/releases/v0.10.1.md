# EngineLink v0.10.1 — More reliable discovery of 2.4 GHz routers

## Why this version exists
Some nearby 2.4 GHz router SSIDs appear only after repeatedly pressing **Scan for networks**. Prior firmware scanned each channel once and Arduino's default active-scan minimum may end a channel after 100 ms if no AP responds, even when the configured maximum is 220 ms.

## Changes
- Run **two asynchronous passes** across channels 1–13 in the user-requested discovery screen. The first pass uses active directed probes with a full 220-ms dwell; the second uses passive beacon listening (300 ms per channel). Retain combined strongest-signal results, with short 130-ms gaps for SoftAP traffic.
- Record the count found by the first pass versus the final combined result. Show pass/channel progress and error metrics, without losing prior findings from the same scan.
- Add **Enter router manually** (SSID + password) to the existing Boat router page. This bypasses discovery; hidden networks can be entered directly. The user may select router mode without needing the router to appear in scan results.
- Preserve the normal **exclusive AP or STA** operation: standalone SoftAP by default; only the explicit user action switches to router-only STA; failure restores the standalone AP after the established 120-second retry window.
- No changes to engine data handling, diagnostics rules or branding.

## Installation and test
Use the USB installer at https://kaelor9.github.io/EngineLink/ **once it displays v0.10.1**. A full USB installation overwrites internal NVS/settings and LittleFS history, not the external SD card. Disconnect engine and NMEA 2000 interfaces for the first bench test.

1. With an iPhone connected to EngineLink standalone Wi-Fi, scan for router SSIDs three times at a fixed location. Record the reported **Found in pass 1** and **Networks found** values in Diagnostics.
2. Check whether the target SSID appears every time. Compare with the router's **2.4 GHz** SSID, not merely the phone's signal indicator; the phone may be associated to a 5 GHz band that ESP32-S3 cannot see.
3. If the target is missing, use **Enter router manually** with its exact 2.4 GHz SSID and password. Test router authentication and subsequent access by the router-issued IP.
4. Verify the EngineLink SoftAP disappears during successful router-only operation; after repeated failed attempts it should reappear in rescue mode.
5. Note the Wi-Fi disconnect reason, RSSI, and scan failures if instability continues.

**Hardware verification required.** CI compilation, UI JavaScript checks and static regression tests cannot guarantee the behavior of a particular radio/antenna/router, including band steering, security configuration, or 3.3 V power integrity.
