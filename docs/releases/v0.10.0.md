# EngineLink v0.10.0 — Network reliability refactor (experimental)

This release focuses on the underlying network architecture, **not** a redesign of the Marine Precision user interface.

## User-selectable connection modes
- **EngineLink Wi-Fi (factory default):** The controller broadcasts its own 2.4 GHz access point and hosts its UI at http://192.168.4.1 and http://enginelink.local. No router is needed.
- **Connect to a router:** The user scans for a visible 2.4 GHz SSID, selects it and enters a password. EngineLink stops broadcasting its access point and joins the router in STA-only mode.
- **Router fallback:** If the chosen router remains unavailable after a 120-second retry window, the standalone access point returns as recovery. The recovery latch survives reboot. Both modes serve the same local HTTP interface.

## Changes
- **Faster boot:** Launch the selected Wi-Fi mode immediately after loading NVS settings, before LittleFS recovery, trip records and SD-card initialization.
- **Event-driven association:** When the Wi-Fi driver explicitly rejects a connection, schedule a new attempt after 3 seconds instead of always waiting 20 seconds. Give an in-progress association 18 seconds before declaring it stuck; a stalled attempt is canceled and retried in separate service-loop steps. The overall 120-second recovery window remains.
- **Reliable mode switch acknowledgement:** Switching from router to standalone no longer disconnects STA before the HTTP confirmation is delivered.
- **Faster browser reconnect:** Probe current origin, mDNS name, remembered router IP and standalone IP in parallel, rather than waiting 1.5 seconds *sequentially* per failed host. A single probe round is bounded at about 1.8 seconds.
- **Isolated throughput test:** The 32-KiB speed test now runs on a dedicated, low-priority HTTP listener on port 82 instead of blocking the primary WebServer on port 80 for up to 30+ seconds on a weak link. Live telemetry remains on port 81, with the original port 80 UI/API unchanged.
- **Improved diagnostics:** Show standalone/router/rescue mode, early retry count and stalled association count.
- **Regression tests:** Guard the two exclusive normal modes, the prompt acknowledgement before disconnect, the independent speed test, startup ordering, parallel host discovery and existing scanning behavior.

## First-install and acceptance test
Full USB web installation at https://kaelor9.github.io/EngineLink/ is appropriate **only when the installer actually displays v0.10.0**. The full USB image overwrites internal settings and history, not a separate microSD card. Disconnect marine engine interfaces and NMEA 2000 for initial bench testing.

1. Flash the board and measure time until its EngineLink SSID appears; connect an iPhone using http://192.168.4.1.
2. Repeat Wi-Fi scans; the list should show visible 2.4 GHz routers and progress channels 1–13 without dropping the phone.
3. Select the router and enter its password. EngineLink SSID should disappear; check router DHCP client list for a new address and load http://enginelink.local from a phone on the same router LAN.
4. Intentionally test a wrong password: after repeated unsuccessful attempts, EngineLink must broadcast its standalone network again.
5. Run the speed test and navigate between pages while it is active. Measure request/handler/loop maximum latency and live telemetry packet losses.
6. Reboot in both modes; verify persistence and mDNS where supported.

**Status:** Automated compilation and unit/static regression tests are required, but cannot verify RF, power supply, Wi-Fi compatibility, WPA modes, router multicast filtering or actual phone/browser behavior on the physical PCB. This is an experimental release until those bench tests pass.
