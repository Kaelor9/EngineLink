# EngineLink 0.8.3 — Wi-Fi channel recovery and independent live telemetry

**Status:** software fix pending ESP32-S3 hardware validation; not a production release.

## Changes
- When the boat router's BSSID/channel is unknown, connect with channel 0 (all-channel discovery) rather than pinning STA to EngineLink's SoftAP channel. On repeated failures, discard stale BSSID/channel information and try unrestricted association, while preserving completed scans.
- A user-initiated Wi-Fi scan suspends a pending disconnected STA association attempt; no retry is scheduled during the scan.
- New read-only live HTTP listener on **TCP 81**. The phone app asks it for `/api/live`; normal port 80 remains a fallback for older firmware or if port 81 is unavailable. Large reports/CSV downloads on port 80 no longer monopolise the live HTTP listener. Other Settings/History requests on port 80 can still wait for a large download.
- LittleFS file writes preserve a `.bak` backup while renaming the new `.tmp` file; boot repairs interrupted renames. Once storage was mounted successfully, a future mount failure does not silently auto-format the partition.
- GitHub download reports **Router disconnected during download** separately from a 20-second stall.
- CI regenerates the embedded `ui.h` from `firmware/ui/app.html` before validation, compilation and release packaging. For local builds, run `python3 tools/build_ui.py` first.

## What is not yet verified
- Builds/host tests must pass in GitHub Actions before merge; no live board/radio testing was possible from this review.
- No claim that one ESP32-S3 radio can avoid a brief AP disruption when a router changes 2.4 GHz channel. It cannot independently use two channels.
- Hardware RF antenna clearance, supply voltage under Wi-Fi transmit load, and router auth/PMF modes remain unmeasured.
- Port 81 live transport during simultaneous downloads, motor load, SD faults and long-run OTA is **not yet bench/boat verified**.
- This update improves recovery but does not implement resumable GitHub firmware downloads or fully asynchronous port-80 handlers.
- Never change the J1708 transmit request beyond read-only `01 43 21 <index> <checksum>`.
