# EngineLink 0.17.1 — router mode joins from a clean start

**Test version, released so it can be installed with the web installer.
Built (pinned core 3.3.12 compile, host tests, source checks); NOT verified
on the board. Router mode on the owner's home router is not fixed until a
report shows it.** Hardware: revision 1 board, ESP32-S3-WROOM-1-N8R8. USB
installation erases settings and internal history; the Wi-Fi update file
keeps them.

## Why

0.17.0 on the home router (2026-11-10): joined in 376 ms at −40 dBm, 10 of
15 pings answered in the first 30 s, then almost none; four `/api/live`
answers and a 304 got through, the app page failed three times, beacons lost
305 s after the join. The owner's bench sketch on the same board and router
answered 117 of 117 pings in its first two minutes and delivered the 110 KB
page five times. One difference between the two is left in how the join
starts: the sketch only ever starts as a station; every EngineLink session
so far switched to the router **after its own Wi-Fi had been up** (the
Arduino core then shuts the radio driver down and builds it again).

## Changed

- **Choosing the router in the app restarts EngineLink**, which then starts
  straight into router mode, exactly as the sketch (about 5 s). Not while a
  trip is running (a restart would end the trip); then it switches as before.
- **The Wi-Fi report says more per router session:** whether it was joined
  straight after a start or by switching from the own Wi-Fi, the country
  code the driver used, and how long after the join the last ping came back
  in under 50 ms.

Unchanged: Standalone, recovery (2 minutes without the router → own Wi-Fi,
back every 10 minutes or from the app), the web server, the app, settings,
engine data, trips, SD, updates.

## Test

Install, set up the router in the app (EngineLink restarts by itself), wait
half a minute, open `http://enginelink.local` or the address from the
router's client list. After 10 minutes, or when it stops answering, send the
Wi-Fi report.
