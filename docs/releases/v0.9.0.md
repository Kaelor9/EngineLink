# EngineLink 0.9.0 — stability hardening (no UI or new features)

**Scope:** Preserve the current user experience, engine-protocol restrictions and existing persisted data. Software changes only; field validation is still required.

## Changes
- **Router scan/reconnect race:** `serviceNetwork()` no longer initiates STA reconnection while an async scan is running. It defers retries without falsely counting another failure.
- **OTA download and manual upload:** application image header validation is independent of packet sizes. The first 48 image bytes can arrive as any number of TCP or multipart chunks; incomplete or invalid headers are rejected. `tools/test_otaheader.cpp` tests every split point and byte-at-a-time delivery.
- **OTA flash failures:** show the actual `Update.begin()` or `Update.end()` error rather than an empty failure message.
- **LittleFS visibility:** write failures and recovery actions are counted; diagnostic JSON includes `fsWriteErrors`, `fsRecoveredFiles` and `fsLastFailure`. Health/life dirty flags are only cleared after successful file writes.
- **No UI alterations, passwords, extra controls, motor commands or new board requirements.**

## Important limits
- The HTTP port-80 server still serializes large requests. Live polling has its separate TCP port 81 as of 0.8.3, which is not a fully concurrent general-purpose HTTP server.
- The motor task is separate but shares a mutex with the main loop. A stress test must verify frame drops and the maximum lock wait under concurrent downloads.
- No live RF, SD removal, power cut, engine operation or hardware OTA test has been performed by this change.
- Valid compile/host tests prove source and regression checks, **not** stable Wi-Fi on this custom PCB.
- ECU transmission must remain restricted to read requests `01 43 21 <index-hi> <index-lo> <checksum>`.
