# EngineLink v0.9.2 — recover the device when a router connection fails

## Incident and motivation
The owner changed from standalone Wi-Fi to the boat router. The status LED repeatedly showed **long green, short blue** (= router unreachable) while EngineLink's own SSID was no longer visible. Neither access path worked. Prior versions kept attempting STA scans and connections in AP+STA mode without an automatic escape, even though ESP32-S3 has a single Wi-Fi radio.

## Changes
- **45-second fail-open:** if EngineLink cannot obtain a router connection/IP for 45 seconds (including after a later disconnect), it stops all STA reconnect attempts and returns to **AP-only** mode. The AP configuration is explicitly recreated on the configured channel, without erasing its password.
- **Remember rescue mode:** the `rhold` flag is persisted in NVS. After a failed router setup the next boot opens the standalone Wi-Fi immediately, instead of entering the same unreachable AP+STA loop.
- **Manual retry:** selecting a router through existing Settings > Boat router clears the hold and tries again. Forgetting a router also clears it. No new buttons, logins or UI modifications.
- **Diagnostics:** existing `/api/diag` includes `routerHold`, `routerFallbacks`, `apMode`, `apDriverSsid` and `apDriverIp` to distinguish Wi-Fi driver configuration from front-end status.
- **Regression test:** `tools/test_routerguard.cpp` verifies deadline, reset and `millis()` rollover.

No engine code, J1708 TX policies, SD data, fuel-history structure or LittleFS files are changed.

## Important limits
- This is a **fail-safe recovery**, not proof of the underlying RF, power or driver failure. The SoftAP may still fail to beacon because of antenna/driver/hardware issues.
- AP+STA on a single ESP32-S3 radio **cannot maintain two independent RF channels**. A connected external router decides the shared channel.
- The tradeoff: if router connection fails for 45 seconds, the device remains standalone until the user manually retries. This protects local access at the expense of automatic background router reconnection during an extended outage.
- A device already locked out on v0.9.1 needs the [non-erasing USB recovery procedure](../USB_RECOVERY.md). **The ordinary installer writes an entire 8 MB merged image, including NVS and LittleFS, and is not safe for preserving data.** The recovery script backs up these partitions and flashes only the application and OTA boot selection.
- CI compile and host tests do not test radio beacons or iPhone association. Verify AP visible within ~45 seconds after failing a router setup, AP-only access to 192.168.4.1, no unexpected resets, persistence after a full power cycle, and normal AP+STA when the router is healthy.
