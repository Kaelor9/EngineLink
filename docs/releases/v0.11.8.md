EngineLink 0.11.8: the web server recovers by itself.

- **The web server can no longer silently stop answering.** In router mode the owner's phone reached the board at its IP address (steady green: connected), but Safari reported "network connection was lost" and "server stopped responding": the board accepted connections and never answered. A likely cause is running out of network sockets (lwIP allows 16 in all; up to 8 kept-open browser connections plus the listeners on 80/81/82, mDNS and others could use them up). Now:
  - at most 4 kept-open connections (was 8), closed after 3 s idle (was 5);
  - a self-check asks the board's own web server (http://127.0.0.1/api/health, no radio involved) every 20 s; after 3 misses in a row it closes all connections and starts the web server again; if it still does not answer 2 minutes later, it saves the totals and restarts the board. Skipped while a request is legitimately busy (downloads, reports);
  - the network report counts self-check misses, web-server restarts and board restarts for it, so the next report shows whether this was the cause.
- Not yet tested on the board. The root cause is not proven; the self-check makes the board recover whatever it is.

Settings, trips, the fuel log and fuel totals are kept.
