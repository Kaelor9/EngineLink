# EngineLink 0.17.4 — the report shows the chip's temperature

**Test version for the web installer. Built (pinned core 3.3.12 compile,
host test, source checks); not verified on the board. Router mode on the
owner's home router is not fixed.** Hardware: revision 1 board,
ESP32-S3-WROOM-1-N8R8. USB installation erases settings and internal
history; the Wi-Fi update file keeps them.

## Why

0.17.3 (the same firmware as 0.17.1) in Standalone, powered from the bench
supply without USB, after a cold power-on: 54–121 kB/s at 24–103 ms a minute
after the start, 195–477 kB/s at 8–27 ms four minutes later; earlier the
same day the same code gave 580–730 kB/s at 7–12 ms. Memory was fine (93 KB
free, no failed allocation). So the link's speed changes by itself with the
time since power-on, in Standalone too. Whether it follows temperature is
not known; the board can measure that itself.

## Changed

- The ESP32-S3's internal temperature sensor is read every 5 s.
- The report shows the temperature now, at the first reading after the
  start and the highest; every speed test is listed with the chip
  temperature and the uptime it was made at; every 30 s piece of a router
  session carries the temperature.

Nothing else is changed: the network code is 0.17.1's.

## How to use it

Power on from cold, open the app on EngineLink's own Wi-Fi and run the speed
test at about 1, 3, 6 and 10 minutes; send the report. The same in router
mode needs nothing extra: the session's 30 s pieces show pings and
temperature side by side.
