# EngineLink v0.11.2 — focused Wi-Fi diagnostics

- Replace the oversized Wi-Fi diagnostics grid with four useful fields: mode, router, successful router IP assignments, and unexpected drops.
- Add **Open readable network report** at `/api/network-report`. This plain-text report includes a 64-entry chronological Wi-Fi event trace and full machine-readable JSON without disclosing the router password.
- Keep the last known successful router IP, Wi-Fi RSSI and channel visible after reverting to rescue AP.
- Correct error 202: **Wi-Fi authentication failed**, not proof that the saved password is wrong.
- Correct rescue status timing and suppress a redundant low-level reconnect call when the native driver has recently reported a connection failure.

**What the v0.11.1 hardware evidence proves:** The board associated with Zyxel_9D27 twice and received a router IP twice, then recorded 33 unexpected disconnects. This proves the problem is not a permanent inability to obtain DHCP but does not yet establish whether RF/power, authentication policy or router behavior caused the drops.

**Validation:** Build/unit checks on GitHub are software-only. Router stability must still be tested on the actual board and a controlled 2.4 GHz WPA2-AES network. Do not treat this version as a confirmed router connectivity fix.
