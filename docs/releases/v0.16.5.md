# EngineLink 0.16.5 — standalone Wi-Fi diagnostics and TX power correction

**Status: compiled/CI only until tested on the EngineLink PCB and an iPhone.**

The owner's USB Wi-Fi report for 0.16.4 (50 s uptime) recorded one
phone joining at +23 s and leaving at +40 s with reason 8 (station
left), with zero successful port-80 HTTP requests. No AP watchdog restart
was recorded. This alone does not prove an ESP32 radio or browser failure;
it also does not confirm the phone received a DHCP address.

- **Access point power:** remove the unverified AP-only 8.5 dBm override
  from 0.16.3. Use the same fixed 19.5 dBm target as the main firmware,
  and recheck after the AP-ready event. The earlier report incorrectly
  claimed 19.5 dBm while the driver reported 8.5 dBm.
- **AP DHCP:** count IP addresses assigned to clients after association.
- **TCP vs HTTP:** count accepted connections on port 80 (separating real external clients
  from the local health check) and HTTP parse failures, independently
  of completed HTTP requests.
- **Report accuracy:** mark STA power-save state as not applicable while
  running the standalone AP.

No changes to the engine protocol, J1708 transmission permissions, fuel
calibration, network-mode selection, passwords, saved data or app UI.

## iPhone acceptance test

1. Join the EngineLink SSID, turn off mobile data for the controlled
   experiment, and verify the Wi-Fi stays joined for 60 seconds.
2. In Safari open `http://192.168.4.1/api/health` (expect `OK`),
   then `http://192.168.4.1/` (expect the application).
3. Export the USB Wi-Fi report and compare `apJoins`, `apDhcpLeases`,
   `httpExternalAccepts`, `httpParseFailures` and `httpRequests`.
4. If no DHCP lease appears, investigate association/DHCP. If DHCP
   appears but zero TCP accepts, investigate IP/routing or phone behavior.
   If TCP accepts occur without valid HTTP, investigate the server.

**Do not claim the connectivity issue is solved until these steps pass
on the hardware.** Updating via a merged USB image can erase saved
settings and data; use the application-only OTA image or backup-first
USB recovery as described in docs/RELEASING.md.
