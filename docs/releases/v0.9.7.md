# EngineLink v0.9.7 — Router association and HTTP diagnostics

## Changes
- Router association uses the saved SSID/password without pinning a previously scanned BSSID or Wi-Fi channel. This supports routers and mesh APs that change channel, BSSID or radio after the scan.
- Remove blocking synchronously rescanning the router in the main-loop reconnect path. Association is initiated asynchronously via the ESP32 Wi-Fi stack with a 20-second attempt interval.
- Give router mode changes a 1.2-second response grace period, allowing the browser to receive confirmation before the active Wi-Fi disconnects.
- Add separate request parsing, handler processing and last slow endpoint diagnostics to identify the remaining source of multi-second web UI stalls.
- Keep existing Marine Precision UI, functionality and **exclusive** network modes: standalone AP or router-only STA.
- The rescue AP remains available after a 45-second failed router connection.

## Installation and acceptance test
Fresh USB flash at https://kaelor9.github.io/EngineLink/ when the page shows **v0.9.7**. This overwrites internal settings and history, not the external SD card. Disconnect engine buses and NMEA 2000 for first bench testing.

Test with the same 2.4 GHz router that was failing: after selecting its SSID and entering the password, move the phone to the router, then open http://enginelink.local or the assigned router IP. Check the router's DHCP leases if mDNS is not forwarded. Watch HTTP parse/handler timings and the slow endpoint in Diagnostics.

**Not validated on the physical PCB.** CI compilation and JavaScript validation cannot establish radio stability or prove the router password/security settings are compatible.
