# EngineLink v0.11.0 — Native router association and predictable standalone recovery

## The two modes are deliberately exclusive

1. **Standalone (factory default)** — ESP32 runs a SoftAP named EngineLink (or the user-selected name). A phone can join this Wi-Fi and access the full local dashboard at http://192.168.4.1 without any router or internet access. This remains the chosen operating mode across restarts.
2. **Connect to a router (explicit selection)** — From standalone the user can scan for a visible 2.4 GHz router or type its SSID and password directly. After a confirmed browser response EngineLink shuts down the SoftAP, switches to STA-only, and asks Arduino/ESP-IDF to associate with the router. When it has an IP from DHCP, the same web interface is available via its router address (and the .local hostname where the LAN forwards mDNS). Router selection remains saved across restarts.

**If a router cannot deliver an IP address for 120 consecutive seconds**, the device leaves station mode and restores the standalone SoftAP. This rescue latch is persisted in NVS to prevent reboot loops; a deliberate user action can start another router attempt.

## Corrective changes after comparing with Marine RGB Light Controller
- **Native auto-reconnect enabled in router mode.** The working Marine RGB Light Controller uses WiFiManager with automatic reconnection. Previous EngineLink revisions disabled it and repeatedly ran their own WiFi.begin / disconnect / retry sequences, potentially interrupting ongoing WPA and DHCP negotiation.
- **A single WiFi.begin per mode selection or boot.** ESP32's driver handles recoverable connection loss, with no user-code interference. Only after a full 30-second unassociated interval may EngineLink issue one last-resort WiFi.reconnect(), at most once per 30 seconds, without rewriting the credentials.
- **Stop Wi-Fi before hostname changes.** The ESP32 Arduino API requires setHostname() before the Wi-Fi interface starts. The existing application previously called setHostname() on an already active interface during mode changes. This release turns off Wi-Fi once *at the intentional mode switch*, sets the hostname, and starts only the desired interface.
- **No periodic UDP traffic to gateway port 9** while connected, removing a non-standard and unnecessary keepalive from the main loop.
- Preserve 120-second rescue mode, full local UI, Wi-Fi network scanning, direct SSID/password entry, engine monitoring, SD, and the separate HTTP workers.
- Add regression checks that fail if manual disconnect/retry logic is reintroduced or AP and STA run together during normal operation. Diagnostics report native auto-reconnect and whether STA is associated.

## Hardware test procedure (required before calling this stable)
1. Install the full USB firmware through https://kaelor9.github.io/EngineLink/ **only when it displays v0.11.0**. The full image can reset internal NVS/configuration and LittleFS history. Do not assume SD data is wiped.
2. With engine bus and NMEA 2000 connectors initially disconnected, verify EngineLink's SoftAP appears on the phone and the dashboard works at http://192.168.4.1.
3. From router setup choose or manually enter the **2.4 GHz** SSID and password. After the acknowledgement the EngineLink SoftAP must disappear. Check the router DHCP client table and use the assigned **IP address** before evaluating mDNS.
4. Verify that reconnecting the phone to the same router makes dashboard and live values available. Test the page repeatedly and inspect Router drops, STA associated and IP in diagnostics.
5. Briefly reboot the router; EngineLink should reconnect automatically. Leave it offline for over 120 seconds and verify rescue SoftAP returns, persists over reboot, and allows a new explicit router attempt.
6. Check 3.3-V power and the ESP32-S3 antenna if radio association is still unstable despite no forced disconnects.

**Important:** A passing ESP32-S3 compilation and static regression tests do not establish actual radio or router behavior on the physical custom PCB. These steps must be verified on the device.
