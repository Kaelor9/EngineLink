# EngineLink v0.11.4 — WPA3 SA Query recovery and accurate Wi-Fi diagnostics

## Field evidence from v0.11.3

Zyxel EX3600-T0 successfully negotiated **WPA3-SAE** and obtained `192.168.1.57`. At uptime 365 seconds it disconnected with Wi-Fi reason 209. Association recovered ~31 seconds later. The earlier 201 (network not found) occurred **before** the first IP, not while a usable router connection was established. The browser measured 17 kB/s router-side against 369 kB/s in standalone; the 32 KiB browser measurement includes setup time.

## Changes

- **Handle Wi-Fi reason 209 correctly**: `WIFI_REASON_SA_QUERY_TIMEOUT` means an unacknowledged WPA3 Protected Management Frames SA Query. This does **not** indicate that WPA3 lacks support or that the router password is wrong.
- **Prompt, non-disruptive recovery:** Arduino-ESP32 v3.3.12 does not include 209 in its auto-reconnectable reason list. Schedule a single `esp_wifi_connect()` request after 2 seconds from the main network loop, never from the Wi-Fi callback and never while still associated. The 30-second last-resort nudge and 120-second rescue AP safety remain in place.
- **Truthful connection counters:** The diagnostics' *unexpected router drops* now count only actual losses of a router connection that had already received a DHCP IP. Failed pre-association/handshake attempts have a separate *pre-connection failures* counter.
- **Speed-test isolation:** Keep the independent 32 KiB download test and additionally record the ESP32 worker's own TCP write duration and write count. The detailed report contains both, to distinguish slow ESP32 writes from browser/HTTP setup delay. No SD, engine task, or Wi-Fi mode changes.

## Hardware validation still required

1. Keep Zyxel's 2.4 GHz network in mixed WPA3-SAE/WPA2-PSK and verify `Last negotiated Wi-Fi security: WPA3-SAE`.
2. Leave it connected, check whether reason 209 recurs, and compare timestamps: the 2-second retry should reduce reconnection delay, though the underlying PMF loss may persist.
3. Send a full `/api/network-report` and a new download test from the same browser/network. Compare `Last 32 KiB server write` against the browser's elapsed time.
4. Verify standby AP-only, deliberate switch to router, rescue after unrecoverable router failure, and updates.

**Important:** CI compile/static tests do not prove WPA3 PMF interoperability with this Zyxel router. The RF/PMF underlying error remains unresolved and may involve the AP's behavior or packet loss. The update makes recovery faster and diagnosis more trustworthy, not a claim of a fully fixed router.
