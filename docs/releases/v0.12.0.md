EngineLink 0.12.0: joins routers the way most ESP32 devices do.

- **WPA2 like most ESP32 products, WPA3 only when the router needs it.** The ESP32 libraries EngineLink is built with always offer WPA3, and with some routers (the owner's Zyxel) the WPA3 login then failed over and over, for whole boots (codes 2/4/202). Shelly, Tasmota and most other ESP32 devices are built without WPA3 and join such "WPA2/WPA3 mixed" routers with WPA2. EngineLink now does the same: its Wi-Fi driver starts without WPA3 (`wifiwpa3.cpp`, link option `-Wl,--wrap=esp_wifi_init`). That works with WPA2 routers and WPA2/WPA3 mixed routers, which together are nearly every home and marina router.
- **Still works with a WPA3-only router.** When the network scan shows that the chosen router only offers WPA3, or the router answers "no compatible security" (codes 210/211), EngineLink starts its Wi-Fi with WPA3 instead, and keeps that for this router. After a router session that never got in, it tries the other mode next time.
- The network report shows the security mode and whether the WPA3 switch is built in. Both release builds check that it is.
- No router change is needed. Not yet tested on the board.

Settings, trips, the fuel log and fuel totals are kept.
