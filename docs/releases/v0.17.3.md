# EngineLink 0.17.3 — 0.17.2's memory change taken back

**Test version for the web installer. Built (pinned core 3.3.12 compile,
source checks); the firmware is 0.17.1's, which ran on the board. Router
mode on the owner's home router is not fixed.** Hardware: revision 1 board,
ESP32-S3-WROOM-1-N8R8. USB installation erases settings and internal
history; the Wi-Fi update file keeps them.

## Why

0.17.2 kept the Wi-Fi's packet buffers in internal memory by taking all
PSRAM for EngineLink. On the board (owner's report, Standalone, 87 s after
the start) internal memory ran out: free 35 KB, **lowest 0 KB, 109 failed
allocations** (1600-byte packet buffers), the low-memory safety valve
opened once, and Standalone fell from about 650 kB/s to 160–460 kB/s.
EngineLink uses too much internal memory itself for the Wi-Fi's buffers to
fit there as well.

## Changed

- 0.17.2's PSRAM change is removed completely. The firmware is 0.17.1 again
  (router mode joins from a clean start; the extra lines in the report).

Not answered by 0.17.2: whether Wi-Fi buffers in PSRAM slow the link to the
home router. Answering it in EngineLink needs about 100 KB of EngineLink's
own tables moved out of internal memory first.
