# EngineLink 0.13.3 — router response and export stability

- Throttle ESP32 Wi-Fi driver mode/status/IP reads in the network service loop to once per second or immediately after an IP event. This targets a previous observed pathological polling pattern that could slow router traffic to a few kB/s.
- Defer automatic transmit-power testing and Wi-Fi channel surveying whenever the app has made HTTP requests within the last 20 seconds, including the first survey after a router connection. The app takes priority over radio diagnostics.
- Temporarily disable deflate compression for **raw trip CSV exports**. A series of v0.13.2 crashes were traced to the compressed raw-export code path (ChunkOut::flush / tdefl_compress_buffer). This avoids that specific code path, at the expense of larger downloads; other exports are unchanged.
- Add CI static regression checks for all three.
- Engine polling, fuel calculations, trip storage, and J1708 protocols are unchanged.

**Compatibility:** ESP32-S3 EngineLink revision 1. Updating through the in-app Wi-Fi application installer preserves settings, trip/fuel data and logs. Do not use the full merged USB image for updates to an installed device.

**Validation required on the actual board:** confirm repeated router-mode speed tests before/after an idle interval and after at least 30 minutes, raw CSV export, zero unexpected crashes, normal trip logging. These source changes cannot eliminate real RF interference, and channel conditions can still require router-side changes. The reported v0.13.2 slow link showed 5.6 kB/s with router ping 293 ms average and 20% packet loss; this is not yet demonstrated fixed in hardware.
